## 1. 目标与结论

设计一套描述符，同时满足以下要求：

1. 在明确支持的 GRASP CSF 格式和态标签范围内，不因丢失 seniority、耦合项或缺失状态而混淆不同 CSF。
2. 结合文件元数据，可以还原规范格式的 CSF 文件。
3. 支持当前 `ml_csf_choosing` 中的 ANN/CNN 筛选，保持 CSF 原始行号与 CI 标签、预测结果和选择索引一致。

建议采用：**每个 Peel 子壳层四个整数 `[N, 2J, v, 2K_printed]`，另存总角动量、宇称和文件元数据。** 子壳层顺序直接采用 `Peel subshells:`，不再增加顺序字段。

该方案适合作为 ANN/CNN 的输入基础，但不能直接替换现有三字段文件。可逆性属于编码正确性；筛选效果属于需要实验验证的模型表现。增加信息可以消除表示层面的碰撞，不能保证网络必然学会所有重要性差异。

## 2. 当前实现与问题来源

### 2.1 完整 CSF 数据与旧描述符不同

`rCSFs/src/complete_csf.rs` 的 `CompleteCsfFile` 保存文件头、轨道表、占据子壳层、可选子壳层态、显式中间耦合项、总角动量、宇称和块边界。`SubshellState` 中保留 `seniority: Option<u8>`。

生成器在枚举子壳层态和耦合时产生完整记录，再通过写出器生成 GRASP 文本。完整数值模型足以服务当前支持格式的写出；不能把旧 ML 描述符视为这个完整模型。

需要准确区分：生成过程会计算累计耦合链，但 `CompleteCsfFile` 持久保存的是**显式打印的稀疏耦合项及其 boundary**，不是每一个边界上都具有非缺失值的完整物理累计角动量数组。

`CompleteCsfFile::descriptor_for` 派生的旧描述符为每个 Peel 子壳层三个整数。它忽略 seniority，把某些省略值与零值混合，并在中间耦合省略时回填可见的子壳层 J；最后一个占据子壳层的第三字段保存总 2J。

实际 Tools 文件转换入口还经过 `csfs_descriptor.rs` 的文本/Parquet 解析路径。因此，实施 V2 不能只修改 `descriptor_for`，必须覆盖文件解析、批处理和导出路径。

### 2.2 已知碰撞示例

当前生成测试 `rCSFs/tests/csf_generation_test.rs::repeated_j_values_keep_distinct_seniority_states_in_table_order` 包含 `4f`（单电子 j=7/2）、占据数 4、总 2J=4 的两个态，seniority 分别为 2 和 4。

| 态标签 | 旧三字段描述符 | V2 子壳层字段 | V2 全局字段 |
| --- | --- | --- | --- |
| v=2 | `[4, 4, 4]` | `[4, 4, 2, -1]` | `[4, +1]` |
| v=4 | `[4, 4, 4]` | `[4, 4, 4, -1]` | `[4, +1]` |

新编码保留真实态标签，无需引入任意的 CSF 唯一编号作为 ML 特征。

### 2.3 分类与回归目标必须分开解释

当前主训练路径使用 `CSFClassifier`，按目标能级进行多标签分类，损失为 BCEWithLogitsLoss。`ml_initializer.py::_build_important_csfs_mask` 主要按 CI 平方阈值生成标签，配置启用时还会加入差分 CI 条件。

因此，不同 CI 系数并不必然意味着分类标签冲突：只有同一描述符在同一目标输出上对应不同标签时，才有直接的分类监督冲突。独立回归路径使用 `log10(max(CI², min_clip))` 作为目标，应按回归目标判断冲突。

即使编码无碰撞，同一 CSF 在不同计算、不同轨道基、不同本征态中的 CI 系数也可能不同。V2 不承诺仅凭 CSF 标签跨所有物理上下文唯一确定 CI 系数；当前各目标能级由不同输出列表达。

## 3. V2 数据合同

### 3.1 子壳层字段

按文件中有序 Peel 轨道表固定分配 M 个位置，每个位置保存：

```text
d_i = [N_i, two_j_i, seniority_i, two_k_printed_i]
```

| 字段 | 含义 | 缺失规则 |
| --- | --- | --- |
| N | 电子占据数 | 未占据为 0 |
| two_j | 原记录打印的子壳层态 2J | 未打印为 -1 |
| seniority | 原记录打印的 seniority 标签 | 未打印为 -1 |
| two_k_printed | 当前占据子壳层之后对应边界上显式打印的中间 2K | 未打印为 -1 |

未占据位置统一为 `[0, -1, -1, -1]`。显式打印的 J=0、seniority=0、K=0 均保存为 0，不能与未打印混淆。未打印 seniority 不代表其物理 seniority 一定为零。

`two_k_printed` 严格表达原记录的打印内容，不沿用旧描述符的回填规则，也不把总 2J 填入最后一个位置。

对于当前记录中第 r 个占据子壳层（r 从 1 开始），该位置的非缺失 `two_k_printed` 对应当前完整模型的 `boundary=r`。若占据子壳层总数为 m，现有规范写出器允许的中间 boundary 为 `2 <= r < m`。这是占据子壳层序号，不是带空轨道位置的 Peel 数组索引。

### 3.2 全局字段与元数据

每条记录另存 `total_two_j` 与 `parity`（-1 或 +1）。逻辑记录包含 `4M+2` 个整数，但物理列应区分轨道特征列和全局列，不要求把两类字段无条件一起输入网络。

数据集还必须保存：

- schema 版本、字段顺序和缺失值约定。
- 有序 Peel 轨道表及足以识别轨道的标签；不同轨道表下的相同数值向量不能直接认定为同一 CSF。
- 原始五行文件头，包括 core/peel 信息。
- 原始记录顺序和对称性块边界。
- 规范文本格式约定，例如 LF 换行。

原始整数数据是还原依据。归一化浮点张量只是训练视图，不承担精确还原职责。行号、块号可以作为辅助列保存，但不能被加载器自动当作 ML 特征。

完整文件往返应保留重复出现的记录。CSF 身份与记录出现位置是两个概念：两个完全相同 CSF 的重复行允许具有相同描述符，以原始行号区分其出现位置，不得为了唯一性自动去重。

### 3.3 固定顺序与支持范围

V2 首版应校验：

- 每条记录的轨道属于 Peel 表，且同一轨道不重复出现。
- 原记录内子壳层顺序与 Peel 顺序一致。
- 显式出现的占据数为正，且不超过子壳层容量；未占据仅由固定数组中的占据数 0 表示。
- 标签、宇称、耦合边界及必要的态组合满足支持范围；有 seniority 时必须有对应的子壳层态。

不符合这些条件的外部输入应明确拒绝，不能静默排序、合并重复轨道或丢弃显式零占据字段。改变耦合顺序可能改变 CSF 的含义。

可逆性合同限定为：对通过上述校验、当前格式能够完整表达的记录和元数据，满足 `decode(encode(CSF)) == CSF`。规范文本可要求字节一致；非规范空白、CRLF 等不能无条件承诺字节还原。

如果未来支持需要额外 alpha 标签才能区分的态，应扩展字段和版本，不能假定 seniority 对所有可能的态体系永久充分。旧描述符丢失的信息不能仅凭旧数组恢复，迁移必须读取原 CSF、保留三行内容的 Parquet，或完整数值记录。

### 3.4 还原流程

1. 读取并校验 schema、Peel 表和记录字段。
2. 按 Peel 顺序取出 N>0 的子壳层。
3. 从数值和 -1 恢复可选子壳层态、seniority，以及带 boundary 的稀疏中间耦合。
4. 恢复总 2J、宇称、文件头、记录顺序和块边界。
5. 使用完整 CSF 写出器生成规范三行文本。

完整往返无需重新枚举态或重新运行 GRASP。输出被筛选的子集时，则按所选原始索引重建块边界和记录数量，不能原样套用完整文件的块偏移。

### 3.5 耦合通道：文件原貌与旧训练补值的区别

V2 的 `two_k_printed` 保存原 CSF 的显式中间耦合值及其省略位置。它不沿用旧描述符的补值，也不对实际耦合值做简单累加。逐级耦合结果本身表达前面子壳层组合后的角动量，不等于把各子壳层 J 数值逐项相加。

| 情况 | 旧三字段的第三通道 | V2 的第四通道 |
| --- | --- | --- |
| 显式打印中间耦合 | 保存两倍角动量值 | 保存相同的两倍角动量值 |
| 未打印中间耦合，第二行有子壳层 J | 用该子壳层 2J 补值 | -1 |
| 两处均未打印 | 0 | -1 |
| 最后一个占据子壳层 | 覆盖为总 2J | -1；总 2J 单独存储 |
| 未占据的 Peel 位置 | 0 | -1，同时 N=0 |

上述旧行为同时体现在 `CompleteCsfFile::descriptor_for` 和 `CSFDescriptorGenerator::parse_csf_into`。旧通道混合了读取值、补值和最终总 J，不能将其视为每个位置都按物理规则补全的累计耦合链。

`descriptor_normalization.rs` 中的前缀和、后缀和累加的是占据相关的耦合上界，用来计算归一化分母，不是在累加 CSF 的实际耦合值。V2 应单独处理归一化语义和缺失值。

为比较 ML 效果，可以另行增加“旧补值规则 + seniority/缺失信息”的派生训练视图，但这只是候选实验，不改变四字段基线，也不能覆盖可逆存储中的 -1。若提供该视图，必须记录训练视图版本并在训练与预测间保持一致。

## 4. ANN/CNN 适配分析

### 4.1 当前网络

ANN 的 `CSFMLPBackbone` 使用 `nn.Linear(input_size, hidden_size)`，支持新的输入维度，主体无需因四字段而重写。

CNN 的 `CSFConv1DBackbone` 支持参数化 channels，当前调用链默认值为 3。网络先按子壳层分组，再转为 Conv1d 布局，卷积核大小分别为 3 和 1，之后展平并进入全连接层。新输入应保持轨道分组：

```text
逻辑输入：[batch, M, 4]
卷积输入：[batch, 4, M]
ANN 输入：[batch, 4*M]
```

Conv1d 的批次、通道、序列布局见 [PyTorch 官方说明](https://docs.pytorch.org/docs/stable/generated/torch.nn.Conv1d.html)。现有 CNN 要求至少三个轨道位置；迁移时应保留明确校验，对更短序列选择 ANN 或另行设计网络。

Peel 顺序提供稳定的轨道位置，但相邻轨道并不涵盖全部耦合关联。现有全连接头能组合卷积输出，实际学习能力仍需实验评估，不能预设 CNN 必然优于 ANN。

### 4.2 总 J 与宇称的输入方式

当前 `training_data_loader` 按单个对称性块对齐 CSF 与第一块 rmix 数据。在满足这一流程前提时，总 J 和宇称为常量，只需存储以便还原，ANN/CNN 可以使用 `4M` 个轨道特征。

应显式校验单块前提，不能从多块数据中不加检查地删除全局特征。若将来支持跨块统一训练，应将总 J、宇称作为全局输入；CNN 在卷积特征展平后再拼接这些字段，不能把它们混入轨道分组。

### 4.3 四通道基线与七通道实验

首版基线使用四通道，保留 -1 哨兵值。神经网络可以接受负数；缺失哨兵并不使训练天然无效。

可选七通道视图：

```text
[N_scaled, two_j_scaled, seniority_scaled, two_k_scaled,
 has_j, has_seniority, has_k]
```

存在标记为 0/1；缺失数值填零，实际零值通过存在标记区分。是否占据可由 N 判断，首版无需额外增加该掩码。四字段存储保持不变，掩码由原始整数派生。

七通道会增加训练内存和计算开销；它是否优于四通道应由实验决定。seniority 首先保留为整数标签，类别嵌入或 one-hot 属于后续实验，不是可逆格式的前置要求。

### 4.4 预处理与物理含义

当前 `initial_csfs.py` 实际传入 `normalize=False`，旁边“启用归一化”的注释与参数不一致。训练入口主要转换 float32，不能假定已有适用于 V2 的特征缩放。

首版可用原始四通道作为可复现实验基线；若启用缩放，应使用明确、可持久化的规则，且训练、批量预测和流式预测共用同一实现。数据驱动的缩放参数仅从训练部分拟合。缺失值不参与有效值统计，不能被当成物理负角动量进行归一化。

旧归一化函数按三字段和旧累计耦合语义编写，不能只把步长 3 改为 4 后复用。尤其 V2 的 K 是显式打印项，而不是补全后的物理累计 J。

若后续增加完整物理耦合链等派生特征，应从经过验证的耦合规则得到，并单独定义训练视图版本；不得通过无依据回填替换原始可逆字段。

建议在 Tools 中设置一个共享的 descriptor schema/训练视图适配模块（拟新增，名称未定）。格式合同由 rCSFs 提供，训练视图归 Tools 所有，不应重新把 ML 编排放回 graspkit。

如公开配置新增描述符版本或掩码选项，还需同步 `ml_module/config_models.py`、示例 TOML、配置加载器和配置 UI。通道数宜从版本与训练视图自动推导，避免要求用户维护几个相互依赖的数字。

## 6. 迁移顺序与兼容性

1. 定义 V2 schema、支持边界及编码/解码；先通过往返测试。
2. 接通 CSF 文本、三行 Parquet 和生成器导出路径，确保相同输入产生相同 V2。
3. 接通 Tools 的加载、四通道基线、ANN/CNN、预测和覆盖检查，验证端到端索引一致。
4. 同步跨 J 分组与需要保留的回归入口，再允许完整工作流切换。
5. 从完整源数据重新生成 V2 描述符，重新训练模型；不要把旧权重默认视为兼容。
6. 完成固定实验对照，再决定是否增加掩码、缩放或派生物理特征。

不能使用“数组长度相同”作为兼容依据；相同长度仍可能有不同字段顺序、Peel 顺序或预处理方式。旧文件缺少版本标识时应通过明确的旧版入口处理，不能自动按 V2 解释。

切换格式时可在验证原始 CSF 顺序与身份完全一致后复用历史选择索引和 CI 标签；否则必须显式重建映射。文件头、块信息和描述符必须成套匹配。

## 7. 正确性与效果验收

### 7.1 编码与还原

- 已知 seniority 碰撞样例在 V2 中不同。
- 未打印与显式 0 分别往返，包括 J、seniority 和中间耦合。
- 空轨道、闭壳层省略、带空轨道位置的耦合边界、不同总 J/宇称、多块和重复记录正确往返。
- 规范文件通过 `CSF -> V2+metadata -> CSF` 后字节一致。
- 子集还原与按原始索引从源文件选出的规范 CSF 一致。
- 错误顺序、重复轨道、非法占据数、错误字段范围、非法边界和不匹配元数据明确报错。
- 在支持态组合中验证 `decode(encode(record)) == record`；不能仅依靠 hash 无碰撞来声称可逆。

### 7.2 ML 接入

- ANN/CNN 的前向输入维度正确，四通道分组不串轨道；七通道另测。
- lazy/eager、训练/预测和普通/流式处理得到相同特征与索引对应关系。
- 两套覆盖检查只读取 N 字段。
- checkpoint 对格式、轨道顺序、预处理或目标顺序不兼容时拒绝复用或明确新建模型。
- 跨 J 分组按经过定义的语义处理 seniority 和中间耦合，不能误合并原本需要区分的组。

现有测试入口包括：

- rCSFs：`tests/complete_csf_test.rs`、`csfs_descriptor_test.rs`、`csf_generation_test.rs`、`csf_generation_pipeline_test.rs`、`descriptor_normalization_test.rs`、`generation_parquet_test.py`、`interaction_test.rs`、`rcsfs_test.py`。
- Tools：`tests/test_bilous_cnn_model.py`、`test_neural_network_entrypoints.py`、`test_streaming_descriptors.py`、`test_train_streaming_descriptors.py`、`test_large_descriptor_streaming_smoke.py`、`test_iterative_training_mode.py`、`test_cross_j_union.py`、`test_train_regression.py`。

按改变后的行为增补测试，不仅验证数组宽度。所有 Python、PyO3 和 Rust 测试使用共享 `graspkit-tools/.venv`；rCSFs 测试不依赖外部 GRASP 可执行程序或私人数据。真实重算评估与自包含单元测试分开。

按更新后的 rCSFs 开发说明，源码更新与 Python 实际加载的扩展需要分别确认：Tools 侧在 `graspkit-tools/` 执行 `uv sync` 刷新安装的 wheel；从 rCSFs 目录运行 pytest 时还需按该仓库指南构建并刷新树内扩展，不能认为更新了源码或已安装 wheel 就自动更新了树内二进制。不要使用 `maturin develop` 改变共享环境的安装方式。性能复测应记录提交号、扩展实际导入路径、构建模式、线程数、机器资源及输入，避免混用不同构建的结果。

### 7.3 筛选效果对照

对照组至少包括旧三字段、新四字段；七通道作为可选第三组。固定原始 CSF 集合、已标注训练索引、目标能级、标签、随机种子方案和选择预算，记录各版本的碰撞数量、冲突标签数量、运行时间及内存。

主要评价：

1. 固定选择数量下，各目标能级重要 CSF 的召回率及漏选情况。
2. 各目标能级保留的真实 CI 平方权重。
3. 相同计算预算下 GRASP 重算后的能级/能级差误差及收敛轮数。

当前主分类训练使用全部累计样本，不再切出验证集。因此离线对照应单独构建未用于训练的已标注评估集，或使用之后计算得到的新标签评价；不能只看训练损失。重复迭代出现的同一 CSF 不应泄漏到训练和评估两边。对旧描述符碰撞组可单独报告，避免用一个平均指标掩盖表示缺陷。

## 8. 实施边界

首版应优先完成可逆性、四通道接入、版本检查和全链路索引一致性。七通道、类别嵌入、完整物理耦合链派生特征、跨块统一训练均为独立后续实验，不是本轮讨论已经证实有效的优化。

本文仅记录方案和必要修改位置，不表示已完成实现、已测得性能提升或已承诺支持所有 GRASP 变体。

### 9.1 报告的实际输入与现象

用户在 512 GB 内存服务器上执行以下命令。最初报告服务器与本地版本一致，随后确认本地两个子仓库此前未更新；因此事故所用的确切提交/扩展构建仍需核实，不能直接认定与本次核对基线完全一致：

```bash
uv run rcsfs csfsgenerate --config gencsfs.toml
```

```toml
[generate]
order = "*"
core = 2
references = [
    "3s(2,i)3p(6,4)3d(10,*)4s(2,*)4p(1,*)",
    "3s(2,*)3p(6,i)3d(10,*)4s(2,*)4p(1,*)",
]
active_orbitals = "8s,8p,8d,8f,8g"
j_min = 1
j_max = 1
excitations = 4
continue_lists = false

[output]
generate_descriptors = true

```

用户报告：内存疑似耗尽，VS Code SSH 界面和新建终端 SSH 连接均失去响应，最终强制重启服务器。用户提供的 GRASP 基准数量为 **77,362,152 条 CSF**，尚未在本地对这个完整输入复核数量和逐条一致性。

更新前的本地受限探针记录：相同输入、2 线程时约 2.95 秒达到 1025.2 MiB RSS，被探针的 1 GiB 阈值终止，未观察到最终结果文件；仅将 excitations 改为 2 后生成 115,657 条 CSF、19,619 个唯一占据组态，采样峰值约 385.7 MiB。探针使用当时共享环境中安装的扩展，未绑定本次核对提交；这些数据仅保留为历史诊断记录，不能作为更新后版本的性能结论，不代表服务器的实际峰值，也没有证明其 512 GB 耗尽具体发生在哪个阶段。开启描述符导出时，当前 CLI 仍使用私有暂存目录，因此“最终目标目录无文件”不能单独证明尚未进入写出阶段。

### 9.2 用户确定的流程约束

采用以下顺序，无论是否请求描述符文件：

```text
解析输入与枚举占据组态
    -> 在内存中生成完整、可逆的整数记录
    -> 全部生成结束，在内存中完成必要的排序与去重
    -> 通过统一转译函数转换为规范 CSF
    -> 写出 CSF，以及按选项写出 Parquet/ML 描述符
```

**不采用生成过程中边产生 CSF 边写盘的方案，也不以磁盘中间结果承担生成或去重。** `generate_descriptors` 仅控制描述符文件是否导出，不控制内部是否使用整数表示。

生成完成后的转译/写出可以逐条遍历最终整数集合，避免再建立一份包含全部 CSF 文本的巨型字符串数组。这不改变“全部生成、排序、去重完成后才写盘”的约束。

这一约束不禁止最终导出阶段的暂存文件/安全发布，也不禁止 Tools 在训练和预测时分批读取已生成的数据。需要禁止的是用生成阶段的磁盘分块替代用户要求的全量内存结果。

### 9.3 当前代码已经使用整数表示，需优化其组织方式

现有生成器的 `CompleteCsfFile` 已经是整数模型。主要值得验证的内存开销包括：

- `append_generated_record` 对每条 CSF 都复制占据子壳层记录；同一个占据组态的许多 CSF 重复保存轨道索引与占据数。
- `enumerate_occupations` 同时持有参考配置枚举列表，`merge_two` 克隆记录及其向量；后续又复制为 `GenerationRequest` 列表。
- `generate_csfs_parallel` 收集所有完整结果；单组态的并行分支合并时还会把分支记录复制到目标结果，出现新旧缓冲同时存活。
- 每个组态结果的头信息、轨道字符串、Vec 容量余量及分配器开销也需计入；不能只统计最终记录的有效载荷。

因此，“改成整数”本身不是新增能力。需要实施的是**共享重复数据、压缩字段、减少深拷贝及控制并行临时内存**。在没有分阶段测量前，不把任何一项单独认定为服务器耗尽 512 GB 的已证实根因。

### 9.4 建议的内部格式：共享占据组态 + 紧凑 CSF 状态

内部格式保持与 V2 语义无损互转，但不要求每条 CSF 都在内存中展开成长度 `4M+2` 的稠密 Int32 数组。

| 层次 | 保存内容 | 共享范围 |
| --- | --- | --- |
| 文件元数据 | Core/Peel 轨道表、标签、格式版本 | 整个结果集合一份 |
| 占据组态表 | 按 Peel 顺序排列的非零轨道索引与占据数 | 每个唯一占据组态一份 |
| 态与耦合数据 | 各占据子壳层的可选 2J、seniority，以及显式中间耦合值和缺失标记 | 每条 CSF 自己的内容，连续存储 |
| 记录/分组索引 | 对共享占据组态和态数据的定位、对称性块及输出顺序 | 用于遍历与稳定排序；不是 ML 特征 |

若按占据组态分组存储，每组的组态身份和记录范围可只存一次，无需强制每条记录重复保存一个 configuration_id。记录长短可按该组的占据子壳层数确定，优先评估组内固定步长是否能省掉逐记录偏移。

字段宽度必须依据支持范围验证：占据数、当前可打印的角动量值和 seniority 可评估采用 u8 与保留缺失码；轨道索引、数量和偏移分别选择足够宽的类型。不能未经范围检查就强制转换，也不能把缺失编码成实际 0。大集合偏移和总数量应使用经过溢出检查的宽整数。

可以用显式状态存在位和耦合存在位，或保留码表达缺失；实现前对比空间和访问成本。原始整数始终是权威数据，归一化浮点张量仅在 ML 使用或导出时派生。

### 9.5 与四字段 ML 描述符的关系

同一套可逆语义允许两种布局：

1. 生成器内部：共享占据组态的紧凑整数布局，用于全内存生成、去重、排序和还原。
2. ML/交换文件：按 Peel 顺序展开的 V2 四字段布局，便于 ANN/CNN 和外部调用。

直接将每条记录存为 `4M+2` 个 Int32，其有效载荷约为 `N * (4M+2) * 4` 字节，尚未包括去重索引、临时结果和容量余量。M 包含很多未占据轨道时，这种稠密表示可能比当前稀疏整数记录更大，不能仅凭“描述符”名称认定更节省内存。

应分别比较现有模型、稠密 V2、共享组态布局的每条 CSF 有效字节数和实际峰值 RSS，再选择内部布局。ML 导出可在全部生成和去重结束后按批次展开，不需要在紧凑结果之外再长期保留整份稠密矩阵。

### 9.6 去重与稳定输出

目前占据组态枚举阶段已有多参考列表合并去重。需测量它能否覆盖目标输入中的全部重叠，再确定是否需要最终 CSF 去重，不能假设每条输出必然重复或必然唯一。

如需最终去重，身份键必须包含轨道身份、占据、完整子壳层态标签、耦合信息、总 J 与宇称，并遵守前文统一顺序及规范表示合同。旧三字段描述符不能作为去重键，否则可能删除 seniority 不同的合法 CSF。

哈希可用于加速，但相同哈希必须做完整键比较。优先评估按占据组态/对称性块局部处理、对记录索引排序或共享数据切片比较，避免将所有完整记录再复制进一个大型 HashSet。保持 GRASP 对称性块顺序及块内首次出现顺序；去重后同步更新计数、块范围和所有索引。

这里的去重针对生成结果中同一物理 CSF 的重复枚举，不改变第 3.2 节对“导入既有文件并做无损往返时保留重复记录”的约定。两个 API 的合同应分别明确。

| `rCSFs/src/csf_generation/occupations.rs` | 保留全内存枚举；减少列表合并时的深拷贝，尽可能移动所有权；共享占据组态表，避免同时保留多个等价的大型任务副本。验证多参考去重和排序语义不变。 |
| `rCSFs/src/csf_generation/mod.rs`：Generator、emit、并行分支收集 | 直接向紧凑整数存储追加态与耦合；复用共享组态身份。分支结果通过移动或保留分段所有权整合，避免先克隆为另一份完整集合；并行工作调度需计入临时内存，但不在生成期间写盘。 |
| `rCSFs/src/complete_csf.rs` 或拟新增的紧凑存储模块 | 定义整数存储、访问器、容量统计与无损转译接口。保留现有公共模型兼容性；不能为了调用旧写出器，先把紧凑全集再次展开为完整旧模型。 |
| `rCSFs/src/csf_generation/pipeline.rs` | 完成全部整数生成后，按需要执行内存去重和稳定排序，最后统一遍历并写出；统计生成条数、去重后条数、共享组态数量及各阶段内存。 |
| `rCSFs/src/csfs_descriptor.rs` | 提供从紧凑记录派生四字段描述符的路径；避免为导出描述符而额外保留全量浮点矩阵。若绕过文本重读，须对齐既有列顺序、计数和元数据。 |
| `rCSFs/rcsfs/cli.py`：`_generate_outputs` | 无论 generate_descriptors 是否为真，使用同一整数生成入口。两种模式生成的 CSF 应一致；描述符导出只发生在最终集合确定之后。 |

需要建立阶段统计：占据枚举、整数 CSF 生成、合并/去重、转译写出、Parquet/描述符导出。报告有效数据大小、分配容量和峰值 RSS 的区别；结合可用内存做预算提示或可配置的提前失败，不能用最终整数大小代表整个进程峰值。

### 9.8 新增验收条件

- 生成阶段不创建 CSF 结果文件或生成数据的磁盘中间文件；第一条 CSF 写出发生在全量整数生成及必要的去重排序之后。
- generate_descriptors 开关只改变附加导出物，不改变 CSF 内容、数量和顺序。
- 紧凑存储与 V2、既有规范写出结果一致，seniority 不同的态不能在去重中合并。
- 不同线程数下输出一致；分支合并和去重不会产生另一份长期存活的全量展开结果。
- 记录每个阶段的 RSS，定位原峰值并量化改进；本地小规模探针不能替代服务器完整输入的压力验收。
- 对用户输入在服务器上验证 77,362,152 条基准数量，并在基准可用时验证规范输出顺序与内容；实测包含去重和导出阶段的峰值，确认低于为操作系统和其他服务预留空间后的内存预算。

本节确定的是用户新增的内存生成策略与实施要求。尚未实施紧凑存储，也未证明该输入能够在现有 512 GB 服务器上安全完成。
